# Reference — DNS record matrix

Records generated by the instruction engine
(`ag_domains::instructions::generate_instructions`).

## By hostname kind

| Kind | Routing records | Ownership |
|---|---|---|
| Apex (`example.com`) | `A @ -> <ip>` (per IPv4), `AAAA @ -> <ip>` (per IPv6), recommended `CNAME www -> <edge-host>` | `TXT _ag-domain.<reg> -> ag-verification=...` |
| Subdomain (`api.example.com`) | `CNAME api -> <edge-host>` | `TXT _ag-domain.<reg> -> ag-verification=...` |
| Wildcard (`*.example.com`) | `CNAME * -> <edge-host>` | `TXT _ag-domain.<reg> -> ag-verification=...` |

`<reg>` is the registrable domain; the ownership record always lives there so a
single proof covers the apex and its subdomains.

## Notes emitted

- Apex with no configured IPs: a note explains apex needs A/AAAA (or provider
  CNAME flattening / ALIAS).
- Wildcard: a note explains TLS requires a DNS-01 challenge
  (`_acme-challenge` TXT) during issuance.

## BIND export

`export_bind_zone` renders the same records as a `$ORIGIN`-anchored fragment;
the apex is rendered as `@`, CNAME values are fully qualified, TXT values are
quoted.

## Apex caveat

Plain `CNAME` is not valid at an apex per DNS rules. Providers offer ALIAS /
ANAME / CNAME flattening; the engine emits `A`/`AAAA` for the apex by default.
