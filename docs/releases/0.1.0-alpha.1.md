# Anti-Gravital v0.1.0-alpha.1

English | Espanol

## Alpha release (testing only)

`v0.1.0-alpha.1` is the first tagged alpha of Anti-Gravital. It is published so
contributors and early users can install the toolchain, scaffold a project and
build small prototypes from a `.ag` schema. It is **not production-ready**:
public APIs may change before 1.0 and the pre-Phase-5 release gate is open
([release gate](../audits/PRE_FASE5_RELEASE_GATE.md)).

- Version: `0.1.0-alpha.1`
- Release date: 2026-11-22
- Distribution: install from source (the verified path). There is no crates.io
  package. Prebuilt binaries are built for four targets; an opt-in alpha
  channel (`AG_INSTALLER_CHANNEL=alpha`) verifies a SHA-256 checksum only and
  is still pending end-to-end verification (#141 remains open).
- Support: best effort. Breaking changes are allowed until 1.0.

## Scope

Included and usable in this alpha:

- Install from source with `install.sh`, `install.ps1` or
  `cargo install --path crates/ag-cli --locked`.
- Scaffold `rest`, `realtime` and `fullstack` projects with `ag new` (guided
  wizard in an interactive terminal, non-interactive defaults in CI).
- Run a local development server with `ag dev`. The CLI default bind is
  `127.0.0.1:8080`, but the generated scaffolds hardcode `0.0.0.0:8080` and
  ignore `BIND` (issue #191); do not expose the dev server on untrusted
  networks.
- Lint and generate from a `.ag` schema with `ag schema lint` and
  `ag generate`: Rust modules, SQL migrations, TypeScript types and client,
  OpenAPI 3.1 and optional AsyncAPI 2.6.
- Inspect and validate configuration with `ag config` and its scriptable
  equivalents; build a release binary with `ag build`.
- Use the implemented standard modules (`ag-auth`, `ag-data`, `ag-cache`,
  `ag-realtime`, `ag-storage`, `ag-observe`, `ag-mail`, `ag-domains`,
  `ag-workers`, `ag-edge`) behind their Cargo features, with native defaults.

## Known limitations

Stated plainly, because hiding them would violate the project's own rules:

- No package-manager install: a Rust 1.99.1+ toolchain is required to build from
  source. The opt-in alpha download channel is checksum-only, with no signature
  or authenticity claim, and its end-to-end verification is still pending.
  The signed-manifest trust anchor (#141, RFC-0030) is not in place.
- The `ag dev` CLI default is loopback, but generated templates bind
  `0.0.0.0:8080` and ignore `BIND` (issue #191). Treat the dev server as
  network-exposed until this is fixed.
- `ag deploy`, `ag migrate` and `ag plugin` are future commands and are not in
  the alpha binary.
- No MCP server or shared machine interface: the seven prerequisites of
  [RFC-0024](../rfc/RFC-0024-mcp-shared-machine-interface.md#9-implementation-prerequisites-review-of-2026-11-21)
  are not met, so no MCP code is authorized.
- The pre-Phase-5 release gate remains open. The 24-hour fuzz gate has not been
  run (CI executes a 60-second smoke test) and final performance evidence on
  stabilized code is pending.
- Generated Rust handlers are deliberate stubs: the framework does not write
  application business logic.
- Public APIs can change until 1.0. No SemVer stability promise applies to
  this alpha.
- Optional integrations (Redis L2, NATS, S3-compatible storage, external SMTP,
  PostgreSQL durable backends) are behind Cargo features; native,
  self-contained defaults are used when they are disabled. Some durable
  PostgreSQL integration tests remain `#[ignore]` because default CI does not
  provision a database.
- Open technical debt is tracked as GitHub Issues (label `tech-debt`);
  [docs/DEBT.md](../DEBT.md) is a frozen historical record.

## Upgrade path

- From an untagged source checkout: update `main`, re-run the installer (or
  `cargo install --path crates/ag-cli --locked --force`) and regenerate
  artifacts from your `.ag` schema. Review generated files before overwriting
  application code.
- From a previous alpha: there is no automated data migration in this alpha.
  Re-run `ag generate` and reconcile the diff by hand; schemas and generated
  outputs are not guaranteed to be byte-identical across alphas.
- To 1.0: a stable API and a documented migration path are planned with the
  1.0 release. Until then, pin the commit or tag you build from.

# Notas de release v0.1.0-alpha.1

> Nota: la seccion en ingles es canonica. Esta seccion puede estar
> desactualizada; si difiere, prevalece la version en ingles.

`v0.1.0-alpha.1` es el primer alpha etiquetado de Anti-Gravital. Se publica
para que colaboradores y usuarios tempranos instalen la herramienta, creen un
proyecto y construyan prototipos pequenos a partir de un schema `.ag`. **No
esta listo para produccion**: las APIs publicas pueden cambiar antes de 1.0 y
la puerta de release pre-Fase 5 sigue abierta.

Incluye: instalacion desde el fuente, creacion de proyectos `rest`, `realtime`
y `fullstack` con `ag new`, servidor local con `ag dev`, validacion y
generacion de artefactos con `ag schema lint` y `ag generate`, configuracion
con `ag config` y builds con `ag build`.

No incluye: paquete en crates.io; el canal opt-in de binarios solo verifica
checksums, sin afirmacion de firma, y su verificacion integral esta pendiente
(#141); `ag deploy`,
`ag migrate` ni `ag plugin`; servidor MCP (no se cumplen los prerequisitos de
RFC-0024); certificacion de rendimiento ni de fuzzing de 24 horas. El servidor
de `ag dev` enlaza todas las interfaces aunque el default de la CLI sea
loopback (issue #191). Los handlers Rust generados son stubs y las APIs pueden
cambiar hasta 1.0.

La tabla de evidencia de verificacion de la seccion inglesa esta pendiente de
que QA la complete; ningun resultado se marca como verificado sin evidencia.
