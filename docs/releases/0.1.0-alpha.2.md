English | Espanol

## Alpha release (testing only)

`v0.1.0-alpha.2` is the second tagged alpha. It keeps everything from
`0.1.0-alpha.1` and adds the 33-template catalog, local deployment artifacts
and the domain/DNS configuration loop. It is **not production-ready**: public
APIs may change before 1.0 and the pre-Phase-5 release gate is open
([release gate](../audits/PRE_FASE5_RELEASE_GATE.md)).

- Version: `0.1.0-alpha.2`
- Release date: 2026-11-22
- Distribution: prebuilt binaries for four targets plus `checksums.txt`, or
  install from source. The alpha installer verifies SHA-256 checksums; it does
  **not** claim signature verification (#141 remains open).
- Support: best effort. Breaking changes are allowed until 1.0.

## New in alpha.2

- **Template catalog**: 33 named templates (`ag new --template <name>`), grouped
  as core, web, API, realtime, infrastructure, AI and testing. 29 carry
  `template.toml` metadata and pass an offline scaffold + `cargo check`
  validation ([gallery](../templates/GALLERY.md),
  [CATALOG](../CATALOG.md)).
- **Local deployment**: `ag deploy plan|apply|status` renders authored Docker
  and Kubernetes artifacts into `deploy/generated/`, with plan ids, no network,
  no cluster and no container daemon required (RFC-0034).
- **Docker and Kubernetes packaging**: optional Dockerfiles, compose files,
  Kustomize bases/overlays and local stacks under `deploy/`, with a
  security-reviewed, loopback-only default.
- **Domain loop**: `ag dns plan|apply|status` and `ag domains attach` resolve a
  `[domain]` declaration in `ag.toml` into validated records with plan/apply,
  per-environment visibility (private by default), no credentials in the repo
  and no live provider unless explicitly configured (RFC-0033).
- **Developer gates**: `scripts/ag-check`, proactive git hooks, weekly
  audit/deny guardrails and reproducible smoke harnesses for releases,
  templates, deploy artifacts and the domain loop.

## Verification evidence

- `ci`: six jobs across four platforms; `quality`, `docs`, CodeQL and
  `guardrails` green on the tagged commit.
- `cargo test --workspace --all-features`, `clippy -D warnings`, `cargo audit`
  (0 vulnerabilities) and `cargo deny --all-features check`.
- `scripts/validate-templates.sh` STRICT_CLI=1: 29 PASS, 0 FAIL.
- `scripts/validate-deploy.sh`: 9 PASS, 3 honest SKIPs (no daemon, cluster or
  kubeconform in this environment).
- `scripts/validate-domain-loop.sh`: 12 PASS, 0 FAIL in a no-network sandbox.

## Known limitations

- No signed releases: checksums provide integrity, not authenticity.
- The pre-Phase-5 release gate remains open (fuzz 24h, benchmarks, open debt).
- No live DNS provider, ACME staging, cluster apply or real mailbox test was
  executed; those gates are blocked by external infrastructure.
- Cloud deploy (Phase 5) is not implemented; `ag deploy` is a local renderer.
- Three CLI modules exceed the 600-line guardrail and are temporarily
  allowlisted under issue #189.

`v0.1.0-alpha.2` mantiene todo lo de `0.1.0-alpha.1` y anade el catalogo de 33
plantillas, los artefactos de despliegue local y el ciclo de dominios/DNS. No es
una version de produccion: las APIs publicas pueden cambiar antes de 1.0 y la
puerta pre-Fase 5 sigue abierta.

Novedades: catalogo de plantillas, `ag deploy plan|apply|status`, empaquetado
Docker/Kubernetes opcional, `ag dns plan|apply|status` y `ag domains attach` con
visibilidad privada por defecto, y compuertas de verificacion reproducibles.

Verificacion: CI verde en cuatro plataformas; 29 plantillas, 9 comprobaciones de
despliegue y 12 del ciclo DNS en verde; auditoria y deny limpios.

Limitaciones: sin releases firmados, compuertas externas pendientes (fuzz 24h,
benchmarks, DNS real, ACME, cluster, buzones reales) y tres modulos temporalmente
exentos del limite de tamano (#189).

## Addendum (2026-11-23) — installer fast path, additive only

This section is a dated, additive note. It does **not** rewrite the release
scope, verification evidence or limitations recorded above, which remain the
historical record of what was verified for `0.1.0-alpha.2` on 2026-11-22.

- **Release status:** `v0.1.0-alpha.2` is now **published** (not a draft) with
  nine release assets. Publication remains a human action under RFC-0032 §4.4;
  no agent changed the release or its workflow.
- **Fast install path:** the installer's default `release` channel resolves the
  version from `[workspace.package].version` in `Cargo.toml` (`0.1.0-alpha.2`,
  not the `VERSION` label), downloads the versioned prebuilt binary for the
  detected platform and verifies its SHA-256 against the release `checksums.txt`
  before installing — no compilation and no toolchain download. On the recorded
  host the explicit `AG_INSTALLER_CHANNEL=source` route took about 21 minutes
  and ran two builds; it is still available as a deliberate choice, and there is
  **no automatic fallback** from `release` to `source`.
- **Progress UI:** a native six-stage view (resolve version, detect platform,
  download, verify SHA-256, install, done) with a deterministic headless mode
  for CI (`AG_INSTALLER_PROGRESS=headless`, also selected by `CI`, `TERM=dumb`,
  `NO_COLOR` or non-TTY stdout). Headless output is one stable
  `[ag-install] N/6 ...` line per stage; the fail-closed checks are unchanged.
- **Integrity, not authenticity:** SHA-256 verification is an integrity check.
  There is no signature, no authenticity claim and no trust anchor; issue #141
  stays open and RFC-0030 is a draft. The release `checksums.txt` covers binary
  assets, not the installer scripts (use `checksums/installers.sha256` /
  `AG_INSTALLER_CHECKSUMS`, and `AG_INSTALLER_BINARY_CHECKSUMS` for an
  out-of-band binary manifest). See
  [Installation Integrity](../security/INSTALLATION_INTEGRITY.md).

### Apendice (2026-11-23) — via rapida del instalador (anadido, no reescritura)

Esta seccion es una nota fechada y aditiva: no modifica el alcance, la evidencia
de verificacion ni las limitaciones registradas arriba para `0.1.0-alpha.2` el
2026-11-22.

- **Estado del release:** `v0.1.0-alpha.2` ya esta **publicado** (no draft) con
  nueve assets. Publicar sigue siendo accion humana (RFC-0032 §4.4); ningun
  agente cambio el release ni su workflow.
- **Via rapida:** el canal `release` por defecto resuelve la version desde
  `Cargo.toml` (`0.1.0-alpha.2`, no la etiqueta `VERSION`), descarga el binario
  precompilado versionado y verifica su SHA-256 contra `checksums.txt` antes de
  instalar; no compila nada. El canal explicito `AG_INSTALLER_CHANNEL=source`
  tardo unos 21 minutos y dos builds en el host medido: sigue disponible y **no
  hay fallback automatico**.
- **Progreso:** vista nativa de seis etapas con modo headless determinista para
  CI (`AG_INSTALLER_PROGRESS=headless`, tambien detectado por `CI`, `TERM=dumb`,
  `NO_COLOR` o stdout no TTY), una linea `[ag-install] N/6 ...` por etapa sin
  cambiar el orden fail-closed.
- **Integridad, no autenticidad:** el SHA-256 es integridad; no hay firma ni
  ancla de confianza. #141 sigue abierto y RFC-0030 es borrador. El
  `checksums.txt` del release no cubre los instaladores (usar
  `checksums/installers.sha256` / `AG_INSTALLER_CHECKSUMS` y
  `AG_INSTALLER_BINARY_CHECKSUMS` para el binario fuera de banda). Ver
  [Installation Integrity](../security/INSTALLATION_INTEGRITY.md).
